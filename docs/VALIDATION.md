# v0.4 검증 결과

AETHERWILD v0.4.0 · Node.js 24.19.0 · Three.js 0.180.0 · Vite 7.1.12

## 규칙 검사

`npm test`: **103개 통과, 실패 0, 건너뜀 0**.

v0.3의 68개 검사에 새 직업 방어구 제작식 24개와 다음 11개 검사를 추가했다.

- 세 직업 각각 5슬롯·소유권 유지·장착/해제·직업/레벨 조건·영웅 장비의 실제 능력치 상승
- 획득하지 않은 포인트/초과 배분/알 수 없는 능력치 거부, 무료 초기화의 포인트 보존
- 주 능력치·체력·지능·민첩의 공격력/HP/MP/회복/치명타/이동 반영
- 장비 해제·초기화 시 HP와 MP 상한 조절, 즉시 회복 악용 방지
- 5슬롯·배분·시점·귀환 주문서 저장과 복원
- v0.3 저장의 장비·인벤토리 유지와 신규 슬롯/포인트 초기화, 손상된 포인트 예산 제한
- 58개 아이템 각각 고유 원화 셀, 모든 몬스터 전리품의 명시적 이미지 매핑
- 귀환 주문서 일회성 소모·없는 아이템 거부·모든 몬스터의 실제 드랍 추첨
- 3인칭 카메라의 눈 위치 보존, 지형·장애물 앞에서 카메라 후퇴 거리 제한

기존 제작/장착 검사도 신규 기본 장비의 추가 능력치를 고려하며, 무기 교체의 공격력 증가와 갑옷 교체의 방어/HP 변화를 각각 확인한다.

## 실제 브라우저 검사

Chromium + SwiftShader에서 실제 WebGL 장면과 입력을 실행했다. 낮은 품질은 1000×700 또는 1100×740이며 높은 품질의 야영지·호수도 별도 렌더링했다. 소프트웨어 GPU 검사에 일반 PC GPU의 성능 수치를 부여하지 않는다. 먼 몬스터의 작은 장식을 거리별로 숨기는 LOD를 적용한다.

### 신규 시스템: 11개

`python3 tests/browser_identity.py`

1. 실제 F1 양방향 전환: 플레이어를 이동시키지 않으며 3인칭에서 WASD·전신 모델·무기 표시가 연결됨.
2. 기본 공격↔스킬·스킬↔스킬 캔슬: 즉시 새 동작 시작, 취소한 피해의 추후/중복 발동 없음, 마나와 재사용 시간 유지.
3. 실제 인벤토리에 5슬롯과 58개 고유 아이템 원화 표시.
4. 버튼으로 장착/해제하여 착용 모델 갱신, 소유 수량 보존, 타 직업 장비 거부.
5. 능력치 버튼과 무료 초기화의 포인트 소모/반환.
6. 몬스터가 귀환 주문서를 바닥 주머니에 드랍 → 수거 → 실제 R 입력으로 한 장 소모·야영지 이동, 다른 몬스터 체력 보존.
7. 세 직업 각각 영웅 장비와 전신 관절 모델을 3인칭 자유 시점으로 렌더링.
8. 지면 지정 운석: 표면 텍스처·요철·별도 균열 형상·화염 꼬리·지연 피해 필드 연결.
9. 화염·빙결·번개·비전·성역·화살비의 서로 다른 형상과 셰이더 렌더링.
10. 암석/점액/물/유기체 타격 효과와 수명 종료 후 메모리 정리.
11. 이어하기에서 장비·능력치·시점 복원.

## 배포본·경로·패키지

- `npm run build`: 성공. 라이브러리 포함 JS 약 712kB, gzip 약 200kB. 500kB 청크 크기 권고는 남아 있으며 빌드 실패는 아니다.
- `node scripts/build-meta.js --check`: 현재 소스/에셋과 배포본의 내용 해시 일치.
- `tests/production_smoke.py`: 개발 접근점 없이 실제 F1, 활 선택/당김/발사, 7종 시작 아이템, 5슬롯, 투구 해제/재장착, 포인트 버튼, WASD로 NPC 접근·E 대화·수락을 실행.
- 새 아이템 원화는 문서 기준의 절대 URL로 변환하여 CSS 폴더에서 상대 경로가 중복되는 문제를 방지. 배포본에서 누락 이미지/JavaScript/셰이더 오류를 검사.
- `scripts/package-release.py`: 소스와 배포본을 함께 압축, ZIP CRC·필수 파일·의존성/Git 제외 확인, SHA-256 체크섬 제공.
- 압축을 푼 새 폴더에서 빌드 해시를 확인하고 Python HTTP 서버와 `play.sh` 실행 경로를 검증한다.

## 검증 범위

레벨·위치·재료를 준비할 때 개발 전용 접근점을 사용한다. 전투/상호작용/보상 경로는 실제 컨트롤러이고, 배포 검사에는 개발 접근점이 없다. 원화·전신 장비·스킬 시각 검토에는 준비한 테스트 캐릭터와 정지된 효과 시점을 사용했다. 이 결과가 1–20레벨 전체 장기 밸런스나 모든 하드웨어의 FPS를 보증하는 것은 아니다. 캐릭터는 직접 만든 절차적 관절 모델이며 실사 스캔·모션 캡처를 사용하지 않는다.
