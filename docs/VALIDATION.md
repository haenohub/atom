## 자동 규칙 검사

`npm test`: **168개 통과 · 실패 0 · 건너뜀 0**.

기존 성장·장비 36종·몬스터 17종·제작·퀘스트·세이브 5칸·경험치/장비 드랍 5배·카메라·구름 정원·궁수 투사체 검사를 유지했다. 추가된 17개 검사는 실제 모션·이펙트·컨트롤러 코드를 사용한다.

- 30/60/144fps에서 120Hz 시뮬레이션 시간 일치, 느린 프레임 최대 6단계 제한.
- 위치·관절 회전 보간과 물리 상태 복원, ±180도 경계의 짧은 회전, 완만한 준비·타격·회복 곡선.
- 서리 구체의 위아래 방사형 파편과 확장, 타격 효과의 8개 실제 렌더 업데이트 유지와 점진적 소멸.
- 운석·비전 폭풍 중앙 효과가 실제 피해 처리보다 먼저 나오지 않음.
- 대지 분쇄의 무료 도약/조준, 빠른 클릭에도 전체 도약 유지, 벽 경로 거부, 착지 단일 피해와 범위 밖 제외·4초 기절.
- 도약 취소/귀환 후 지연 돌격 없음, 도약 중 Shift가 기력을 소모하거나 대쉬를 예약하지 않음.
- 돌진참의 실제 11m 이동, 암살 표식의 20m 경계와 최초 적중 후 최대 5회 도약.

## 배포 빌드와 웹 경로

`npm run build`와 소스/에셋 지문 검사를 통과했다. `/atom/` 하위 경로에 실제 `dist`를 놓고 `production_smoke.py`에서 개발 접근점 없이 DOM과 키/마우스로 새 저장 칸, 활 장전/최대 당김/발사, F1, 장비 장착/해제, 능력치 버튼, 실제 걸어서 NPC 접근·E 대화·의뢰 수락을 검사한다.

GitHub Pages는 `.github/workflows/pages.yml`을 통해 현재 작업 브랜치에서 자동 검사·빌드·배포한다. 기존에 설정한 `github-pages` 배포 브랜치 허용 규칙을 사용한다. GitHub에 올린 소스와 별도로 실제 Actions 실행의 배포 완료 상태를 확인한다.

최종 ZIP은 CRC와 SHA-256, 빌드 지문을 검사하고, ZIP 안의 `dist` 파일을 실제 검사한 `/atom/` 배포 빌드와 바이트 단위로 비교한다. 의존성 폴더 없이 새 폴더에 해제해 `play.sh`의 HTTP 실행도 확인한다.

배포 빌드의 위 실제 입력 검사도 모두 통과했다. JavaScript·셰이더·이미지 오류가 없고 개발 접근점은 포함되지 않았다.
