## 실제 Chromium 검사

시스템 Chromium + SwiftShader WebGL에서 개발 서버의 실제 장면과 컨트롤러를 실행했다. 낮은 품질 검사는 1000×700 또는 1100×740이며, 야영지/호수 시각 검토는 높은 품질과 2048 그림자로 별도 실행했다. 일반 하드웨어 GPU의 성능을 측정한 결과는 아니다.

### 새 의뢰·전리품: 8개

`python3 tests/browser_adventure.py`

1. E로 NPC 대화 → 버튼으로 수락, 반복 수락 불가.
2. 전사 준비 중 피해 없음 → 실제 타격 시점 한 번 피해, 검의 회전/위치 변화.
3. 여섯 체형의 관절 보행·공격·피격 자세.
4. 사망 시 시체 유지/붕괴, 자동 지급 없이 주머니가 중력으로 낙하.
5. 미수거 주머니와 처치 의뢰가 새로고침 뒤 복원, E로 정확히 한 번 획득.
6. 원래 의뢰인에게 돌아가 보고하고 한 번 보상 수령.
7. 납품 재료 소모, 후속 의뢰 해금, J에 6개 의뢰 표시.
8. 완료 의뢰·진행 의뢰·수거한 주머니 제거 상태 저장.

### 모션·전투 시점: 4개

`python3 tests/browser_motions.py`

- 몬스터 준비 중 피해 없음, 물러나면 회피, 근처에 남으면 타격 시점에 한 번 피해.
- 심판이 검을 들어 올리고 0.42초 이후 한 번 피해.

- 플레이어 부활 후에도 미수거 전리품 유지, 시체 정리, 몬스터 재생 시 체력·회전·크기 복구.

NPC의 플레이어 쪽 회전도 확인하고 높은 품질에서 야영지와 호수를 실제 렌더링하여 캡처했다.

## 배포본과 패키지

- `npm run build`: 성공. 라이브러리 포함 JS 약 685kB, gzip 약 191kB. 500kB 청크 크기 권고가 남아 있으며 빌드 오류는 아니다.
- `node scripts/build-meta.js --check`: 소스·에셋과 배포본 일치 확인.
- `python3 tests/production_smoke.py`: 개발 접근점 없이 배포본의 화살 선택·당김·발사·인벤토리·아이콘을 실제 입력으로 검사. WASD로 레아에게 접근하고 E로 대화하여 의뢰 수락까지 확인.
- `python3 scripts/package-release.py`: 소스와 배포본을 함께 압축하고 ZIP CRC·필수 파일·불필요한 의존성 제외를 확인. SHA-256 체크섬 제공.

## 검증 범위

브라우저 검사는 위치·레벨·재료를 준비할 때 개발 전용 접근점을 사용하고, 입력/대화/보상은 실제 게임 경로로 실행했다. 프로덕션 검사에는 해당 접근점이 없다. 전직과 최종 콘텐츠까지 자연스럽게 진행하는 장기 밸런스나 기기별 FPS를 검증한 것은 아니다. 캐릭터는 직접 만든 절차적 관절 모델이며 스캔 기반 실사 모델·모션 캡처는 사용하지 않는다. 멀티플레이와 모바일 터치는 범위 밖이다.
