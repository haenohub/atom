## 배포 빌드와 웹 경로

`npm run build`와 소스/에셋 지문 검사를 통과했다. `/atom/` 하위 경로에 실제 `dist`를 놓고 `production_smoke.py`를 실행해 개발 접근점 없이 DOM과 키/마우스로 새 저장 칸, 활 장전/최대 당김/발사, F1, 장비 장착/해제, 능력치 버튼, 실제 걸어서 NPC 접근·E 대화·의뢰 수락을 검사한다.

GitHub Pages는 `.github/workflows/pages.yml`을 통해 현재 작업 브랜치에서 자동 검사·빌드·배포한다. 기존에 설정한 `github-pages` 배포 브랜치 허용 규칙을 사용한다. GitHub에 올린 소스와 별도로 실제 Actions 실행의 배포 완료 상태를 확인한다.

`production_smoke.py`의 위 실제 입력 검사도 모두 통과했다. JavaScript·셰이더·이미지 오류가 없고 개발 접근점은 포함되지 않았다. 최종 ZIP은 CRC와 SHA-256, 빌드 지문을 검사하고, ZIP 안의 `dist` 파일을 실제 검사한 `/atom/` 배포 빌드와 바이트 단위로 비교했다. 의존성 폴더 없이 새 폴더에 해제해 `play.sh`의 HTTP 실행도 확인한다.
