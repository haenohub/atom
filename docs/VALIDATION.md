## 실제 브라우저 검사

Linux Chromium + SwiftShader WebGL 환경에서 확인했다. 소프트웨어 렌더링의 처리 속도를 고려해 최종 탐험 검사는 1000×700 뷰포트로 실행했고, 지속 피해의 완료 대기는 최대 60초로 설정했다. 기존 기능에 대한 검증 조건은 유지했다. 이 환경의 FPS를 일반 PC GPU 성능으로 제시하지 않는다.

### 새 조작 회귀 검사: 7개 통과

`python3 tests/browser_revision.py`: **7개 통과, JavaScript/셰이더 오류 0**.

1. 화살 스킬 선택만으로는 발사·마나 소모·쿨다운 시작이 없고, 장전 상태가 HUD에 표시됨.
2. 실제 마우스 누름으로 당김, 최대 당김 게이지, 놓을 때 강화된 물리 화살 생성 및 마나/쿨다운 적용.
3. 당기는 중 메뉴를 열면 당김이 취소되고 놓아도 발사하지 않음.
4. 마법 범위 미리보기와 우클릭 취소. 취소 시 마나/쿨다운 비용 없음.
5. 좌클릭 확정 후 범위 안 두 대상에 피해, 밖 대상은 피해 없음. 마법 투사체 생성 없음.
6. 서리 결계 확정과 빙결 상태 적용.
7. 새 아이콘 아틀라스가 스킬 창과 HUD에 실제 통합됨.

### 전투·물리 검사: 12개 통과

`python3 tests/browser_combat.py`: **12개 통과, JavaScript 오류 0**.

- 세 직업 각각 실제 마우스 기본 공격으로 처치. 궁수는 당겼다 놓는 입력, 마법사는 기본 지면 파동으로 확인.
- 여섯 전직 각각 두 전직 스킬의 선택/확정/마나/쿨다운 처리. 화살은 발사, 범위 마법은 지면 확정 절차를 포함.
- 실제 이동 구현에 고정 시간 간격을 적용해 낙하 피해·지면 착지, 수영 수면, 고체 장애물 충돌 확인.

테스트는 특정 상태를 준비할 때 개발 서버의 접근점으로 위치·레벨·재료를 설정했다. 따라서 1레벨부터 20레벨까지 자연스럽게 진행하는 전체 소요 시간이나 장기 밸런스를 검증했다고 주장하지 않는다. 전직 검사는 시전 경로와 자원 처리에 대한 검사이며 모든 지형/대상 조합의 전수 검사는 아니다.

## 빌드와 실행

- `npm run build`: 성공. JS 번들은 약 654kB, gzip 약 181kB. Three.js를 포함한 청크의 500kB 권고는 남아 있으며 빌드 오류가 아니다.
- `node scripts/build-meta.js --check`: 새 배포본과 현재 소스·에셋의 일치를 확인.
- `bash play.sh 4173`: 최신 빌드를 다시 설치하지 않고 Python HTTP 서버로 실행하는 경로 확인.
- 배포 서버의 HTML, 숲 재질 PNG, 능력 아이콘 PNG, 빌드 메타데이터가 모두 HTTP 200으로 제공됨.
- `python3 tests/production_smoke.py`: 배포본에서 개발용 접근점이 없는 상태로 화살 선택·최대 당김·발사·새 인벤토리와 아이콘을 실제 입력으로 확인. JavaScript/셰이더 오류 0.
- 마법 지면 미리보기와 조작 화면은 추가로 실제 렌더링해 캡처했다.

## 범위와 한계

새 재질·식생·조명·아이콘·UI·효과를 적용했지만 브라우저용 절차적 3D 모델을 사용하는 게임이다. 스캔 기반 실사 그래픽이나 상용 RPG 수준의 캐릭터 애니메이션을 제공한다고 주장하지 않는다. 실제 하드웨어 GPU별 FPS, 장기 플레이 밸런스, 모든 브라우저 조합, 멀티플레이, 모바일 터치는 검증 범위 밖이다. 기존 localStorage 저장 슬롯과 캐릭터 형식은 유지했다.
